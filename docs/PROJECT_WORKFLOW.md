# 爬壁焊缝检测机器人统一工作流

## 1. 文档定位

本文是 version.1 的统一研发、部署、运行、验证和归档入口。它把项目中重复出现的操作顺序与跨模块约束合并起来；具体消息字段、算法参数和组件命令仍以链接的专项文档和组件 README 为准。

本工作流已审阅本机 Codex 归档目录（`%USERPROFILE%\.codex\archived_sessions`）中 2026-08-04 至 2026-08-14 的 11 个归档会话文件。审阅只提取纯文本消息与会话元数据，没有读取图片；重复请求、中断轮次、临时路径和未完成设想已折叠。最终内容仍以正式代码、设计文档、数据来源和结构化结果为准，未经代码或实验复核的聊天结论不作为验收证据。

## 2. 系统边界与职责

系统由爬壁底盘、双 RGB-D 焊缝视觉、横向滑轨探头和相控阵/TOFD 超声成像组成。

| 模块 | 主要职责 | 禁止越界 |
| --- | --- | --- |
| 底盘与滑轨 | 运动、磁吸安全、限位/急停、INS 融合、轨迹规划、地图记忆、执行视觉对中目标 | 不依赖 GPU 或网络完成安全停止 |
| 视觉 | 顶部相机全局寻缝；探头相机局部对中；分割、中心线、RGB-D 三维投影和候选置信度 | 不直接发送电机底层指令 |
| 超声 | 采集 FMC/PWI/TOFD 原始数据，预处理、波束合成、缺陷显示与定量 | 不承担底盘或滑轨安全闭环 |

推荐三设备部署：底盘实时设备、视觉计算机、超声计算机各一台。两设备备选中，底盘安全控制保持独立，视觉和超声共用计算机前必须完成 CPU、GPU、USB、磁盘和网络压力测试。详见 [部署与时间同步](DEPLOYMENT_AND_TIME_SYNC.md)。

## 3. 坐标、时间与数据契约

统一使用 SI 单位。机器人表面坐标定义为前方 `+X`、左侧 `+Y`、离开钢板 `+Z`；滑轨正方向沿 `+Y`。顶部相机外参固定，探头相机随编码器位置动态变化，二者按序列号绑定且分别标定。

跨设备数据的 Header 必须填写采集时刻，不能填写网络接收时刻。首选 IEEE 1588 PTP；不具备硬件条件时使用 chrony/NTP 并实测最坏偏差。相机设备时钟和超声采集卡 tick 均须保存到统一时基的映射参数。

视觉和超声按采集时间向底盘请求插值后的位姿、IMU 和滑轨状态。时间偏差超过门限时保存原始数据，但禁止进入定量空间融合。字段、频率、QoS 和最小落盘信息见 [底盘数据契约](CHASSIS_DATA_CONTRACT.md)。

## 4. 环境准备

### 4.1 底盘

在 Ubuntu/WSL 的纯 ASCII 路径准备 ROS 2 Jazzy、Gazebo 与 `robot_localization`，再执行依赖安装和 `colcon build --symlink-install`。中文项目目录可作为档案位置，但接口生成构建应复制到如 `~/wcr_v1/ros2_ws` 的路径。

### 4.2 视觉

进入 `code/weld_vision/weld_seam_mvp`，使用组件脚本创建虚拟环境并安装训练或运行时依赖。部署机仅安装推理、ONNX、相机驱动所需依赖；训练环境与现场运行环境分离。

### 4.3 超声

进入 `code/ultrasonic_imaging/ultrasonic-imaging`，按 `pyproject.toml` 安装包及测试依赖。实机采集驱动应保持在硬件适配层，成像核心只接收标准化 RF、阵元几何、材料/楔块参数和采集上下文。

## 5. 底盘、滑轨与地图研发流程

1. 先验证底盘 URDF、轮系、磁吸安全状态、里程计和 IMU 方向。
2. 完成 INS/里程计融合，静止、直行、转向和时间跳变分别测试。
3. 滑轨驱动实现统一命令/状态接口，完成归零、正负限位、软行程、故障、急停和 watchdog。
4. 视觉只发布米制候选中心线和对中误差；底盘按置信度、消息年龄、单次修正和行程门限执行。
5. 同帧多条中心线先按对称距离去重，再依据行驶方向、前视位置、可达性、置信度和历史地图连续性评分。
6. 焊缝与障碍物转换到任务局部地图，持久化地图用于焊缝 ID 连续、任务恢复和在线规划；实时安全传感器仍是防碰撞依据。
7. 目标点模式和离散曲线模式都必须支持障碍物在线增删、移动与重新规划；旧轨迹取消后先输出零速度，再从当前位姿生成新轨迹。
8. 规划边界除机器人包络和安全裕量外，还应预留控制跟踪误差；验收同时检查终点、整条规划线段和实际轨迹的连续最小净空，不能只检查离散航点或“已到达”状态。
9. 曲线航点较密时采用连续速度与前视跟踪，避免逐点停车；速度提升必须在曲率、制动距离、磁吸余量和净空复验通过后进行。

接口和降级行为见 [探头相机与滑轨](PROBE_CAMERA_AND_RAIL.md) 与 [多焊缝跟踪和地图](MULTI_SEAM_TRACKING_AND_MAP.md)。

## 6. 双相机视觉流程

### 6.1 顶部相机

顶部相机负责较大视野的焊缝搜索和任务级轨迹生成。流程为彩色/深度同步、深度对齐、图像归一化、焊缝区域分割、形态学清理、骨架/中心线提取、有效深度筛选、相机坐标反投影、外参变换和地图关联。

### 6.2 探头相机

探头位置推荐 RealSense D405 作为当前基线，约 `42 x 42 x 23 mm`，采购前仍需复核最新机械图、保护窗、USB 弯头、视场和工作距离。其任务是为探头横向滑轨提供局部对中依据，不替代顶部相机全局规划。

每帧投影使用该相机自己的内参、深度比例、外参标定，以及图像采集时刻插值的滑轨位置。缺少动态外参、深度、采集时间或同步状态时拒绝输出控制目标。

### 6.3 模型训练与发布

1. 核验数据来源、许可、图片与标注是否真实存在且能逐项对应；只有标签或引用路径而缺少原图的数据不能直接用于训练。按物理序列/采集组划分训练、验证和测试，避免相邻帧泄漏。
2. 训练二值焊缝分割模型，记录数据版本、配置、随机种子和 checkpoint。
3. 在固定测试集同时评价区域指标与中心线指标，不能只报告 Dice/IoU。
4. 导出 ONNX，比较框架模型与 ONNX 输出，并在目标视觉计算机测量延迟、显存、吞吐和丢帧。
5. 发布模型、模型卡、哈希和结构化结果；图片预览属于可重建材料。

当前固定测试集为 223 张，结构化结果记录 Dice `0.986679`、IoU `0.973708`、像素准确率 `0.994575`；223/223 获得有效中心线，平均对称距离 `3.320839 px`，5 px 覆盖率 `92.1049%`。这些是现有数据集结果，不等同于储罐现场性能。

## 7. 超声成像流程

1. 为每次任务固化材料声速、楔块延迟、阵元坐标、采样率、增益、PCS、探头与软件版本。
2. 原始数据先完成轴顺序标准化、去直流、时间零点、频带处理、坏通道屏蔽和可选增益补偿。
3. FMC 使用全矩阵采集和 TFM/DAS；PWI 按发射角计算传播时间并相干叠加；TOFD 保留每条 A 扫与机器人位姿的采集时刻关联。
4. 输出包络和 dB 图前保留原始 RF 动态范围；相干因子等抑噪权重应可配置并有无权重对照。
5. 定位、尺寸、SNR/CNR、分辨率、耗时和失败样本分别记录，结果回写任务 ID、样本索引和空间位置。
6. 合成 TOFD A 扫用于软件接口、回归测试和参数敏感性研究；公开实验数据用于验证读取和成像链路。两者都不能替代目标材料、目标厚度、实际探头与耦合条件下的标准试块和现场数据。

基线示例中 FMC 数据为 `64 x 64 x 512`，处理约 `1.5623 s`，峰值深度 `20.75 mm`；PWI 为 `9 x 64 x 512`，处理约 `0.2546 s`，峰值深度 `21.0 mm`，耗时约为 FMC 的 `16.3%`。TOFD 半解析合成测试用于算法验证，不能作为现场 POD、法规认证或目标材料能力证明。

## 8. 联机任务状态链

以下是整机集成的目标状态链。当前仓库已具备消息、同步、规划、滑轨和部分融合核心，但仍应在目标 ROS 2/Linux 设备上逐节点核对实际接线，不能仅凭接口文件判定整条状态机已经完成。

```text
IDLE
  -> TIME_SYNC_READY
  -> CHASSIS_AND_RAIL_HOMED
  -> CALIBRATION_VALID
  -> GLOBAL_SEAM_SEARCH
  -> APPROACH_AND_MAP
  -> LOCAL_PROBE_ALIGNMENT
  -> COUPLING_CHECK
  -> ULTRASONIC_ACQUIRE
  -> IMAGE_AND_QUANTIFY
  -> RESULT_COMMIT
  -> NEXT_SEGMENT or SAFE_STOP
```

每次状态转换记录 `task_id`、时间、软件/模型/标定版本和原因。视觉丢帧、置信度低、时钟失锁、上下文插值失败、滑轨限位、耦合异常、磁吸不足或通信中断均触发保持、降速或安全停止，不使用陈旧目标继续运动。

## 9. 标定与验收顺序

1. 电气安全、急停、磁吸、限位和失电行为。
2. 底盘/滑轨方向、编码器比例、重复定位和机械间隙。
3. 两台相机内参、深度比例、时间戳域和独立外参。
4. 探头相机动态滑轨外参及声学中心偏置。
5. INS 坐标、协方差、静态漂移和动态轨迹。
6. 超声材料声速、楔块延迟、阵元原点、标准试块和耦合稳定性。
7. 三设备时间同步、延迟、丢包和数据回放。
8. 单模块、半实物、整机空载、标准试块和目标工件逐级验收。

验收报告必须区分测试函数数量、实际通过的测试、仿真结果、合成数据结果和实机结果。现有仓库的结构化证据可以证明软件基线，但不能替代目标储罐现场试验。

## 10. 证据与归档

证据优先级为：原始采集与标定记录、结构化机器可读结果、测试日志、最终报告、预览图片、聊天描述。每次任务至少保留原始 RF/必要传感数据、采集时间、位姿/滑轨上下文、标定 ID、软件/模型版本、结构化结果和失败原因。

GitHub 只发布轻量可复现集合；原始数据和历史材料留在本机或对象存储。完整边界和发布检查见 [项目归档与发布清单](ARCHIVE_MANIFEST.md)，数据恢复见 [数据集说明](../datasets/README.md)。

## 11. 已知限制与下一阶段

- 双相机、保护结构、耦合剂污染和振动条件尚需实机标定与压力测试。
- 当前公开超声数据与目标 Q245R/Q345R 储罐材料存在域差异，必须补采标准试块和目标焊缝 RF。
- 连续速度模式的一个仿真规划结果出现约 `-17.33 mm` 的规划边界净空，应在提升速度前修正规划/膨胀参数并复验。
- ROS 2/Gazebo 全链路应在纯 ASCII 的目标 Linux/WSL 路径完成最终构建和冒烟测试。
- 新增决策必须回写代码、专项文档或结构化测试结果，避免再次只存在于聊天中。
