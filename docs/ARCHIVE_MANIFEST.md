# 项目归档与发布清单

## 1. 两层归档

项目采用两层归档，避免把约 4.72 GB 的历史下载、原始数据和可重建产物直接放入普通 Git。

| 层级 | 位置 | 内容 | 用途 |
| --- | --- | --- | --- |
| 本机完整档案 | 当前项目目录 | 正式代码、原始数据、历史工程、实验产物、参考资料 | 溯源、重建和后续筛选 |
| GitHub 交付仓库 | Git 跟踪集合 | 正式代码、模型、结构化结果、技术文档、最终报告、数据来源与清单 | 协作、审查和版本发布 |

`.gitignore` 只控制发布边界，不删除本机文件。

## 2. GitHub 唯一可信版本

| 类别 | 路径 |
| --- | --- |
| 项目入口 | `README.md` |
| 统一研发与运行流程 | `docs/PROJECT_WORKFLOW.md` |
| 底盘 ROS 2 | `code/chassis_simulation/ros2_ws` |
| 焊缝视觉 | `code/weld_vision/weld_seam_mvp` |

| 视觉交付模型 | `models/weld_vision/segmentation` |
| 可核验结果 | `results` 中的 JSON、CSV、Markdown 和日志 |
| 数据来源和恢复说明 | `datasets/README.md` 及被放行的数据集文档 |
| 最终技术报告 | `deliverables/大型承压储罐爬壁式智能超声检测机器人技术研究与系统设计报告_系统集成与验收扩充版.docx` |
| 关键交付物哈希 | `SHA256SUMS.txt` |

同一指标出现多份时，结构化结果优先于预览图、临时文档和对话描述；最终报告优先于阶段性报告。

## 3. 本机保留但不上传

| 内容 | 原因 |
| --- | --- |
| `archive` | 旧/重复 ROS 下载、不相关工程、实机遗留代码、虚拟环境、失败构建和候选数据 |

历史文件没有自动删除。确认有独立备份、许可记录和不再需要后，才可人工清理。

## 5. 发布前审计

1. `git status --short --ignored` 检查正式文件与忽略项。
2. 确认没有访问令牌、密码、私钥、设备账号、个人路径或未授权数据。
3. 确认暂存区没有超过 GitHub 单文件限制的文件，并检查提交总体积。
4. 运行三个组件可在当前环境执行的测试；ROS/Gazebo 全链路在目标 Linux/WSL 环境复验。
5. 验证 Markdown 相对链接和 `SHA256SUMS.txt`。
6. 提交到 `main`，记录 commit hash；必要时为交付版本创建带注释标签。

## 6. 对话整合范围

已审阅本机 Codex 归档目录（`%USERPROFILE%\.codex\archived_sessions`）中的 11 个归档 JSONL，时间覆盖 2026-08-04 至 2026-08-14。全部会话均与本项目有关，去重后归并为 ROS 2/底盘、视觉、超声和系统集成四条主线。只解析纯文本消息和元数据，未打开会话中的图片或音频。

整合时删除了重复提问、中断轮次、临时命令故障和已被后续实现取代的早期设想；保留可由代码、文档或结构化结果复核的最终结论。原始会话含个人路径及过程性信息，不进入 GitHub 包。会话主题索引和吸收结果见 [统一工作流](PROJECT_WORKFLOW.md#12-归档会话去重索引)。

## 7. 手动发布步骤

1. 解压轻量交付 ZIP 到一个新的纯 ASCII 路径。
2. 在解压目录执行 `git init -b main` 和 `git add .`。
3. 执行 `git commit -m "Initial project archive"`。
4. 在 GitHub 创建空仓库后执行 `git remote add origin <仓库地址>`。
5. 执行 `git push -u origin main`。
6. 推送后在 GitHub 页面复核模型、最终 DOCX、三个代码组件和 Markdown 链接；大数据按 `datasets/README.md` 另行恢复。
